## 깊이

`period=002` 로 `per`·`page` 를 바꿔 가며 실제로 돌려받은 개수와 마지막 `prstRnkn` 을 적는다.

**분야 코드 (`I` = 인문, A 아닌 모든 코드)**

```
per=20  page=1 → 20개, 1~20위
per=50  page=1 → 20개, 1~20위     (per 을 올려도 20개)
per=100 page=1 → 20개, 1~20위     (per 을 올려도 20개)
per=20  page=2 → 0개 (빈 배열, ymw 도 None)
per=50  page=2 → 0개
per=100 page=2 → 0개
per=20  page=3 → 0개
per=50  page=3 → 0개
```

**전체 (`A`)**

```
per=20  page=1  → 20개,   1~20위
per=50  page=1  → 50개,   1~50위
per=50  page=2  → 50개,  51~100위
per=50  page=3  → 50개, 101~150위
per=50  page=4  → 50개, 150~200위
per=50  page=5  → 0개
per=20  page=10 → 20개, 181~200위
per=20  page=11 → 0개
per=100 page=2  → 100개, 101~200위
per=100 page=3  → 0개
per=100 page=1  → 깨진다: IncompleteRead(80273 bytes read)   ← 2회 재현
per=200 page=1  → 깨진다: IncompleteRead(154482 bytes read)
```

**결론: 분야별은 진짜로 20위까지가 한계다.** 화면의 「20개씩 보기」 드롭다운과 쪽 넘김은
전체(`A`) 목록에서만 의미가 있다. 분야 칩을 누른 상태에서는 `per` 을 올려도 `page` 를 넘겨도
20개를 넘지 못한다 — 코드 주석에 적힌 「분야별은 20개까지만 준다」는 **맞는 말이었다.**

전체(`A`)는 **200위까지** 받을 수 있다 (201위부터 빈 배열). 지금 `SCAN_DEPTH=500` 은 과하고,
`PER=50` 은 적절하다. `per` 을 100/200 으로 올리면 page=1 응답이 중간에 끊기므로
(같은 바이트 수에서 재현되니 일시적인 네트워크 문제가 아니다) **`PER=50` 을 유지해야 한다.**

## 우리 책 다섯 권

「등수」는 `period=002` + 해당 분야 코드의 종합 주간 분야 목록(최대 20위)에서 찾은 `prstRnkn` 이다.
20위 밖이면 이 API 로는 등수를 알 수 없고, 괄호에 상품 상세페이지 주간베스트 배지 값을 참고로 적었다.

| 책 | 쓰던 코드 | 그 코드로 찾은 등수 | 맞는 코드 | 맞는 코드로 찾은 등수 |
|---|---|---|---|---|
| 칼 융의 내면수업 | `I` 인문 | **12위** | `I` 인문 (그대로) | **12위** |
| 완벽한 원시인 | `I` 인문 | 20위 밖 (배지: 인문 65위) | `I` 인문 (그대로) | 20위 밖 |
| 프로이트의 감정수업 | `I` 인문 | 20위 밖 (배지: 인문 230위) | `I` 인문 (그대로) | 20위 밖 |
| 무한의 부 | `c` 자기계발 | 20위 밖 (배지 표기 없음) | `c` 자기계발 (그대로) | 20위 밖 |
| 우리는 서로의 전부이자 지옥이었다 | `g` **청소년** | 20위 밖 — 분야 자체가 틀렸다 | `C` **에세이** | **6위** |

### 배지와 API 가 다르게 나온다 (주의)

상품 페이지 주간베스트 배지의 분야 등수는 이 API 의 분야 목록 등수와 **다른 값**이다.
배지 쪽 분야 구분이 더 거칠다 (칩에는 없는 「시/에세이」라는 이름을 쓴다).

- 칼 융의 내면수업 — 배지 「인문 19위」 / API 분야 목록 **12위**
- 우리는 서로의 전부이자 지옥이었다 — 배지 「시/에세이 12위」 / API 에세이 목록 **6위**

둘을 같은 칸에 섞어 쓰면 안 된다. 「종합 주간 분야」로 화면에 적을 값은 API 쪽이다.

## 결론

- **분야 코드를 바꿔야 하는 책: 1권.**
  『우리는 서로의 전부이자 지옥이었다』 — `g`(청소년) → **`C`(에세이)**.
  지금은 청소년 베스트 20위를 뒤지고 있어서 영원히 못 찾는다. `C` 로 바꾸면 바로 6위로 잡힌다.
  `cat` 표기도 「시/에세이」가 아니라 「에세이」가 맞다 (화면 칩 이름).
  나머지 네 권의 코드(`I`, `I`, `I`, `c`)는 전부 맞다 — 안 찾히는 건 코드 탓이 아니라 20위 밖이기 때문이다.

- **몇 위까지 받을 수 있나:** 분야별은 **20위까지**(한계 확인됨, 더 넘겨도 빈 페이지).
  전체(`A`)는 **200위까지**. 분야 20위 밖은 지금처럼 상품페이지 배지로 보는 수밖에 없다.

- **`ranks.py` 를 어떻게 고치면 되나 (한 문단):**
  `BOOKS['pyoryu']` 의 `catCode` 를 `'g'` → `'C'` 로, `cat` 을 `'시/에세이'` → `'에세이'` 로
  고치는 것이 전부다 (`path` 는 교보 분류 경로니 그대로 둬도 된다). `collect()` 의 `byCat`
  분기도, 20개 한계 주석도, `PER=50` 도 그대로 두면 된다 — 주석은 사실이었다. 덧붙여 전체
  목록이 200위에서 끝나므로 `SCAN_DEPTH` 를 500 에서 200 으로 낮추면 `totalWeeklyAll` 등
  deep 서피스에서 쓸데없는 빈 페이지 요청 6회가 매번 줄어든다(동작은 안 변한다). `PER` 은
  절대 100 이상으로 올리지 말 것 — page=1 응답이 끊겨서 `IncompleteRead` 로 죽는다.
  분야 코드는 하드코딩해도 되지만, 바뀔 가능성을 생각하면 `/bestseller/total/weekly` HTML 의
  `filterData.list` 에서 `codeWrth`/`codeWrthName` 을 읽는 쪽이 안전하다. 코드는 대소문자를
  구분하니 (`I`≠`i`, `g`≠`G`) 옮길 때 주의.
